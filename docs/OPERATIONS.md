# Эксплуатация Glazza 0.1

## Сеть и доступ

По умолчанию доступ к панели только с loopback хоста, порт 8080. NVR UI — 8971 с собственной авторизацией Frigate. Порты внутреннего API Frigate 5000 и анализатора 8090 не опубликованы.

Для удалённого доступа используйте SSH-туннель либо TLS reverse proxy. Если включён TLS, установите `GLAZZA_SECURE_COOKIE=true`. Корректно передавайте исходные Host и схему запроса; доверяйте forwarded headers только известному reverse proxy. Не публикуйте unauthenticated NVR API.

Один администратор создаётся при первом старте БД. Пароль в БД — scrypt. Сессии имеют HttpOnly / SameSite=Strict cookie, срок 12 часов и отдельный CSRF token для изменяющих запросов. Вход ограничен 10 неуспешными попытками с адреса за 5 минут. Лимитер локален процессу и сбрасывается при рестарте. Многопроцессный запуск Uvicorn запрещён для этой версии из-за единственной очереди и внутрипроцессного лимитера.

RTSP credentials хранятся в локальной БД и конфигурации Frigate; ответы API их не раскрывают. Шифрования БД на уровне приложения нет: используйте шифрование диска и ограничение доступа к серверу. Резервная копия содержит секреты. Исходящие уведомления в Telegram/почту не реализованы; журнал и тревоги доступны в панели.

## Конфигурация Frigate

`config/config.yml` управляется Glazza. Кнопка «Применить» полностью генерирует его из камер и зон в БД и затем вызывает перезапуск Frigate. Ручные изменения этого файла будут заменены при следующем применении. Перенос существующего Frigate deployment не поддерживается: используйте отдельный экземпляр, поставляемый с Glazza.

Запись: движение — 1 день, alerts — 7 дней, detections — 3 дня, snapshots — 7 дней. Журнал Glazza — 30 дней (`GLAZZA_RETENTION_DAYS`). У готового или окончательно неуспешного задания локальная копия анализируемого видео удаляется через 24 часа. Новые / выполняющиеся задания не удаляются. При длительном отключении анализатора очередь требует наблюдения.

CPU-модель Frigate подходит для первоначальной проверки подключения. Поддерживаемую плотность камер надо измерять. Профиль `compose.gpu.yaml` относится только к PyTorch-анализатору, не к Frigate.

## Поведение при сбоях

- При отсутствии NVR панель работает и показывает «Нет связи», а камеры — «Нет сигнала».
- При недоступной модели очереди не выдаются фиктивные результаты. На время недоступности сервисов задания сохраняются.
- При ошибке анализа — до 3 попыток, затем ошибка с возможностью ручного повтора, пока файл сохранён.
- После рестарта API незавершённые `running` задания возвращаются в очередь.
- Источник + идентификатор события + тип образуют ключ дедупликации. Периодическая синхронизация не стирает решение оператора.
- После сбоя опрос продолжает сохранённый cursor с перекрытием. Переполненные временные окна делятся рекурсивно. Старые активные объекты проверяются отдельно (до 500 за цикл).
- До подключения первой камеры приложение не создаёт реальные события.

## Резервная копия и восстановление

```bash
# Из корня проекта, во время отсутствия изменений настройки камер
python3 scripts/backup.py --data data
```

Команда делает SQLite online backup и копирует `.env` / конфигурацию. Архив видео, модели и исходные uploads в этот backup не входят. Для их сохранения копируйте `media/`, `models/`, `data/jobs/` отдельно; при необходимости остановите сервисы на время копирования.

Восстановление на отдельной копии проекта:

```bash
docker compose --profile nvr --profile ai down
# Заменить дату на выбранную копию; это намеренная замена данных.
cp backups/<timestamp>/glazza.db data/glazza.db
cp backups/<timestamp>/config.yml config/config.yml
cp backups/<timestamp>/.env .env
# Если остались WAL/SHM от старой базы, сохранить их в отдельной папке до замены.
# Восстановить владельца согласно GLAZZA_UID/GLAZZA_GID из .env.
docker compose --profile nvr --profile ai up -d
```

Перед заменой сохраняйте текущую БД и её `-wal` / `-shm` отдельно. Не оставляйте WAL от другой БД рядом с восстановленным файлом. Для сброса пароля используйте локальную административную процедуру с остановленным API: создайте новый scrypt-хеш через `app.store.password_hash`, обновите запись пользователя параметризованным SQL и удалите сессии. Изменение `.env` само по себе не меняет пароль уже созданного пользователя.

## Не реализовано / не принято

Роли, несколько организаций, HA, WebRTC в панели Glazza, push-уведомления, настройка зон по расписанию, интеграция со СКУД, long-running live action inference, автоматическое разбиение длинных записей, юридический допуск конкретного применения и коммерческие права на сторонние веса. Это явные границы первой версии.
