# Универсальная Glazza: организации и объекты

## Что реализовано

В одной установке можно создать организации и объекты, например сеть с несколькими супермаркетами, отдельный офис, склад и учебное заведение. Организация группирует объекты; камеры принадлежат объекту. Шесть профилей задают стартовые модули: универсальный, образование, розница, склад/производство, офис/ЖК, парковка/территория.

Это **организационная структура для одного доверенного администратора**. Фильтр объекта не является границей доступа: администратор может читать и менять все объекты, камеры, записи и реестры. Роли сотрудников, независимые организации с изоляцией данных, лимиты клиентов и SaaS-биллинг в этой версии не реализованы. Нельзя выдавать учётную запись общей установки независимым заказчикам как изолированные кабинеты. Для них используйте отдельные установки.

## Настройка

1. Обновите исходники, создайте резервную копию SQLite и пересоберите контейнеры обычным порядком.
2. Откройте «Объекты», создайте организацию и объект. Выберите профиль и стартовый набор модулей. Профиль можно сменить; интерфейс заново предлагает его исходные модули, перед сохранением проверьте флажки.
3. В «Привязке камер» выберите объект для каждой камеры. При добавлении камеры из конкретного объекта привязка устанавливается автоматически. В режиме «Все объекты» новая камера или загруженное видео относится к объекту `default` («Первый объект»).
4. Переключатель сверху фильтрует обзор, камеры, карту, события, задания анализа и допуск. Страница управления объектами показывает все камеры, чтобы их можно было переносить. Состояние NVR и моделей общее для установки.
5. Для анализа камеры включите её «Анализ событий объекта», установите нужные веса и примените конфигурацию Frigate. Загрузка видео выполняется в выбранный объект; при отсутствии модулей видеоанализа API отклоняет загрузку.

## Модули и ограничения

| Модуль | Что происходит |
|---|---|
| Люди | Базовый модуль, включён всегда: детекция person во Frigate и запись |
| Запретные зоны | Создание intrusion только у объектов с включённым модулем |
| Возможная драка | Короткие задания с камеры планируются только при включённом модуле; нужны VD-MIL или резервный VadCLIP |
| Проверка посетителей | События из настроенных зон только при включённом модуле; локальные YuNet/SFace и ручная проверка |
| Возможная кража | Экспериментальный общий адаптер VadCLIP, отдельные веса; не специализированный детектор сокрытия товара и не сверка оплаты |
| Движения лица | Только MediaPipe blendshapes; отключён по умолчанию у новых объектов; не вывод об эмоциях или намерениях |
| Очереди, сокрытие товара, СИЗ, транспорт, кассовые операции | Запланированы. API отклоняет попытку включить их, UI блокирует флажки |

Новый профиль магазина включает людей, запретные зоны и возможную драку. Не включает распознавание посетителей, мимику и экспериментальный анализ краж автоматически. Профиль не обучает модель заново и не подтверждает её пригодность для отрасли.

Параметр `modules` передаётся внутреннему анализатору: ненужные модели действий и мимики не запускаются для задания. Если выбранные модели не загружены, задание не получает фиктивный успешный результат. Даже уже полученные детекции проверяются против актуальных модулей объекта перед созданием карточки. Изменение модулей не удаляет историю и сохранённые решения.

## История и допуск

Миграция добавляет существующие камеры, события, задания и допуски в `default`. Старые активные функции этого объекта сохраняются для совместимости; новый объект получает более узкий отраслевой набор. Миграция идемпотентна и не очищает данные.

Объект события и задания фиксируется при создании. При переносе камеры прежние события и выполняющиеся задания остаются на прежнем объекте. После переноса могут существовать исторические события той же камеры в разных объектах. Идентификаторы камер по-прежнему уникальны во всей установке, как требует общий Frigate.

Сопоставление лица ищет только действующие шаблоны **объекта события**. Охранник не может подтвердить вход человеком из реестра другого объекта через API. Для допуска человека на нескольких объектах создайте отдельные записи. Перенос камеры не переносит реестры лиц и историю решений. Это ограничение логики допуска, а не авторизация между независимыми клиентами.

Контроль зон и лиц, возможные драки и экспериментальные кражи остаются сигналами для просмотра. Точность, пропускная способность и задержка в магазинах, на складах и других объектах не приняты. Существующие подключения видео поддерживаются в рамках возможностей Frigate/FFmpeg; универсальная поддержка любой камеры не обещается.

## Проверки

- `python -m pytest -q`: миграция, объекты, фильтры API, история после переноса камеры, границы реестра лиц, отключённые и планируемые модули, авторизация и CSRF.
- `python tests/browser_platform.py`: создание организации и магазина, блокировка планируемых модулей, создание камеры на объекте, фильтр и мобильная ширина.
- Ранее добавленные `browser_smoke.py` и `browser_admission.py` проверяют совместимость старых сценариев.

Следующие независимые этапы: роли и права по объектам, настройка времени действия правил, доставка тревог и эскалация, интеграция с кассами/СКУД и отдельная приёмка отраслевых детекторов. Они не выданы за готовые функции этой версии.
