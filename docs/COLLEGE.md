# Пилот Glazza в колледже

Основной сценарий: **камера → фрагмент с людьми → модель насилия → заметный сигнал → просмотр охраной**. Система не идентифицирует учащихся, не определяет виновника и не принимает дисциплинарных решений. Мимика для этого сценария не нужна.

## Подключение драк

Для уже установленного проекта:

```bash
git pull --ff-only
python3 scripts/models.py fight
docker compose --profile nvr --profile ai up -d --build
docker compose --profile ai restart analyzer
```

VD-MIL: CC BY-NC 4.0. Для коммерческого использования автор требует письменное разрешение. Образовательное учреждение само по себе не означает, что любое внедрение соответствует этим условиям; проверьте конкретное использование до эксплуатации.

1. «Анализ видео»: «Возможная драка» должна показывать «Модель загружена».
2. Подключите одну камеру и включите «Контроль драк и анализ событий»; примените конфигурацию Frigate.
3. «Система»: контроль драк должен показывать проверку фрагментов с людьми. Убедитесь, что в истории появляются успешные короткие задания при движении людей.
4. Загрузите короткую разрешённую для проверки запись: результат должен содержать VD-MIL, число окон и оценки. Отсутствие сигнала не подтверждает отсутствие драки.
5. При сигнале откройте видео и сохраните решение. Повторные срабатывания в пределах 30 секунд объединяются; может быть пропущен отдельный эпизод рядом по времени.

Начните с коридора или входа с различимыми людьми. Слишком дальний план, перекрытия толпой и низкая частота кадров снижают качество. Обнаружение человека во Frigate запускает анализ фрагмента; если человек пропущен, анализ драки тоже может не запуститься.

## Что измерить перед дежурством

Соберите отдельный набор разрешённых записей с ваших камер. Нужны обычная перемена, бег, объятия, игры, уборка, спортивные движения, плохой свет и известные эпизоды конфликтов. При постановочной проверке используйте безопасную имитацию без ударов и травм. Не используйте один и тот же набор одновременно для подбора порога и оценки итогового качества.

Запишите:

- сколько известных эпизодов система обнаружила и сколько пропустила;
- сколько ложных тревог приходится на час каждой камеры;
- время от начала эпизода до появления карточки, включая очередь и запись;
- число неуспешных заданий и пропущенных окон при полной нагрузке.

Веса уже обучены; **дообучения на конкретном колледже нет**. Начальный порог 0.8 и три последовательных окна — параметры пилота. Увеличение порога/числа окон уменьшает число сигналов, но может увеличить пропуски и задержку. Зафиксируйте настройки после проверки на отложенных записях.

## Практические границы

Фрагмент запрашивается через 20–26 секунд после его конца, затем проходит очередь и анализ, панель обновляется каждые 10 секунд. Время реакции на реальном сервере не измерено. Это видеопомощник оператора с задержкой, а не гарантированный канал немедленного вызова охраны. Отдельных уведомлений на телефон пока нет.

При перегрузке очередь ограничена, после большого отставания старые окна пропускаются с записью в аудит. Процессор, GPU, число камер и разрешение нужно подбирать по фактическим измерениям. Не оставляйте статус «модель готова» единственной проверкой: следите за успешными заданиями и тестовым сигналом.

Для реальной приёмки остаётся подключить камеры колледжа и выполнить описанную проверку. Публичные примеры в `tests/real_fight_smoke.py` проверяют интеграцию, а не пригодность для конкретного объекта.
