# Модели

## Что действительно установлено

Файлы моделей не коммитятся в Git. Панель запрашивает состояние анализатора: `missing` (нет файла), `error` (ошибка проверки / загрузки), `ready` (конструктор модели успешно выполнился). Один найденный файл не даёт статуса `ready`.

VD-MIL и MediaPipe скачиваются установщиком. VadCLIP требует отдельного официального UCF-Crime checkpoint. Статус готовности модели не означает принятую точность на вашем объекте.

## VD-MIL: детектор возможной драки / насилия

- Автор: Roger Figueroa Quintero. [Исходный проект](https://github.com/roggerfq/violence-detection-mil), CC BY-NC 4.0, коммерческое использование только с разрешением автора.
- Исходники и classifier: commit `836434843e9f5936030a99e84a2d4e063995465f`.
- MoViNet-pytorch: commit `40bdc3ee608836fdf4edff49b53a7da5a5af1394`, MIT.
- Обучение по описанию автора: RWF-2000 + SCVD, драки и стрельба. Выход бинарный **насилие**, без различения этих действий. Карточка «Возможная драка» требует просмотра.
- Установка: `python3 scripts/models.py fight`; checkpoint и backbone доступны прямо в upstream, VadCLIP не требуется.
- Все URL и фиксированные SHA-256: [`analyzer/fight_artifacts.json`](../analyzer/fight_artifacts.json). Проверяются при установке и перед импортом / загрузкой. При несовпадении модель не запускается.
- Исходники скачиваются отдельно, сохраняются неизменёнными вместе с уведомлениями; не включены в собственный MIT-код. Веса загружаются без сети. Для legacy classifier разрешён ограниченный набор PyTorch-классов через `safe_globals` и `weights_only=True`; небезопасного fallback нет.
- Предобработка: 8 fps, BGR → RGB, resize 172×172, значения /255. Окна 8 кадров с шагом 4; MoViNet-A0 causal, сброс activation buffers перед каждым окном, L2-нормализация признаков, trained MLP 2048→1024→512→1.
- В отличие от upstream графика, **нет min/max-нормализации оценок внутри ролика**: такая нормализация делает локальный максимум почти единицей даже у спокойного видео. Используется сырой sigmoid score.
- Порог по умолчанию 0.8, три соседних окна выше порога; это 2 секунды наблюдения. `.env`: `GLAZZA_FIGHT_THRESHOLD`, `GLAZZA_FIGHT_WINDOWS` (2–8), `GLAZZA_TORCH_THREADS` (по умолчанию 2). Применение: `docker compose --profile ai up -d --force-recreate analyzer`.
- В ответе есть сырые scores, peak, порог, число окон, начало/конец каждого интервала и `checked`. Оценки не являются вероятностью правонарушения.
- В коротких заданиях от камеры выполняется только анализ драки. Загрузка MP4/MOV выполняет все доступные модели. Когда VD-MIL готов, он приоритетен для драк; VadCLIP остаётся для краж и резервного детектора драк.

## MediaPipe Face Landmarker

- Источник: https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker
- Файл: https://storage.googleapis.com/mediapipe-models/face_landmarker/face_landmarker/float16/1/face_landmarker.task
- SHA-256: `64184e229b263107bc2b804c6625db1341ff2bb731874b0bcc2fe6544e0bc9ff`.
- Обёртка: MediaPipe 0.10.21, CPU XNNPACK.
- До 4 лиц на кадр; до 120 выбранных кадров на видео.
- Выход: максимальные значения 52 blendshape-коэффициентов по наблюдавшимся лицам и количество кадров с лицами. Максимумы могут относиться к разным людям и моментам; идентификация / отслеживание личности отсутствуют.
- Это описание движений лица, не надёжный вывод о внутренней эмоции или намерении.

## VadCLIP

- Исходник: https://github.com/nwpu-zxr/VadCLIP
- Commit: `c41067f07d252efcda18008bea367886070c33b0`.
- Код: Apache-2.0. Код CLIP в upstream требует сохранения соответствующих уведомлений; Glazza скачивает исходный репозиторий отдельно и не переименовывает его в собственную модель.
- Архитектура: CLIP ViT-B/16 + временной Transformer + GCN + обученные prompts.
- Официальные параметры: длина 256, ширина 512, 1 attention head, 2 temporal layers, окно 8, prefix/postfix 10, 14 классов.
- Официальный checkpoint должен содержать `clipmodel.*`: backbone берётся из него, поэтому на запуске нет скрытого скачивания CLIP.
- Поддерживаются обычный state dict и словари с `model_state_dict` / `state_dict`; допускается префикс `module.`. Несовместимые параметры отклоняются.

Установщик делает две правки upstream:

1. `DistanceAdj`: жёсткий `.to('cuda')` заменён на `.to(self.sigma.device)` для корректного CPU/GPU выбора.
2. `from pkg_resources import packaging` заменён на `import packaging`.

Выборка: один кадр каждые 16 исходных кадров; 10 пространственных crops из upstream `crop.py`, инференс по каждому crop, усреднение вероятностей классов. Кадры декодируются с сохранением пропорций и полями в 640×360, затем upstream нормализует crop. Вход длиннее 256 samples делится на сегменты. Это интеграционный адаптер, а не воспроизведение опубликованной benchmark-метрики: точность и последствия resize / агрегирования отдельно не валидированы.

`Fighting`, `Assault` → `fight`; `Shoplifting`, `Stealing`, `Robbery`, `Burglary` → `theft`. `Burglary` не используется вместо контроля зон. Для тревоги нужны два соседних выбранных кадра выше порога (по умолчанию 0.75). Порог **не калиброван**, уверенность модели не является вероятностью преступления.

## Приёмка на объекте

1. Собрать разрешённые для обработки записи с целевых камер: разные смены, освещение, перекрытия и ракурсы.
2. Разметить реальные события и похожие нормальные действия; исключить пересечение train/test по исходному видео и камере, если проводится дообучение.
3. Отдельно измерить recall по событиям, precision, ложные тревоги на камеру-час, задержку и пропуски при перегрузке.
4. Настроить пороги только на калибровочном наборе. Финальный test не использовать для подбора.
5. Проверить работу при потере камеры, рестарте API и анализатора, заполнении диска.

Модель действий вызывается после окончания события Frigate. Длинное событие более 120 секунд отклоняется и получает статус ошибки; сегментация длинных событий и непрерывное детектирование драки — последующая работа. Источником истины для допуска служит приёмка на реальных видео, а не число unit-тестов.
