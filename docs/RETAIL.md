# Glazza для магазина

Glazza отбирает короткие эпизоды для рабочего места оператора. Сигнал содержит камеру, время, исходную запись и основание для просмотра. Сотрудник магазина решает, требует ли эпизод дальнейшего разбора. Подтверждение потери товара и суммы ущерба требует независимой проверки магазином.

## Выбор режима

| Режим | Какие эпизоды попадают в журнал | Что нужно магазину |
|---|---|---|
| Маршрут от полки до выхода | Frigate проследил одного человека от полки до зоны выхода и не зарегистрировал посещение кассовой зоны. Сигнал появляется после завершения трека при наличии клипа. | Одна камера видит все три зоны, Frigate записывает видео и обнаруживает людей. Отдельные веса VadCLIP и GPU для этого правила не требуются. |
| Маршрут по трём камерам | Glazza связывает проход по времени, зонам и признакам одежды. Оператор может открыть записи полки, кассы и выхода. При обходе наблюдаемой кассы получает два клипа на проверку. | Три камеры одного магазина, размеченные зоны, детекция людей, доступные снимки и архив. |
| Анализ поведения по видео | Модель VadCLIP выделила интервал с последовательными наблюдениями класса Shoplifting или Stealing. Оператор видит оценку и может перейти к этому моменту. | Профиль магазина, включённый модуль возможной кражи, камера с анализом событий, рабочий анализатор с весами. Для коммерческого применения отдельно выясните условия использования весов. |

Камера может видеть, как покупатель прошёл мимо кассы с пустыми руками. Автоматические правила могут пропустить действительную кражу. Если включить оба источника, один эпизод может дать карточку маршрута и отдельную карточку модели. По видео система не устанавливает личность покупателя, наличие товара в сумке или оплату в POS. Самообслуживание, оплата через приложение, несколько касс или выходов вне кадра требуют отдельной оценки пригодности ракурса. Если зоны находятся на разных камерах, настройте межкамерный маршрут.

## Визиты и связи между камерами

Один магазин может использовать две независимые функции. **Визиты** показывают движение от входа через подключённые камеры. **Маршрут полка → касса → выход** подбирает записи для проверки конкретного прохода. Например, для магазина с десятью камерами можно включить все десять в схему визитов, а в правило проверки назначить три камеры: №1 у полки, №5 у кассы и №10 у выхода.

### Входная камера и временный ID

1. Подключите камеры к одному розничному объекту, включите детекцию людей, проверьте время камер, состояние потоков и получение снимков Frigate. Начните с двух соседних ракурсов, на которых хорошо различима одежда.
2. На входной камере нарисуйте зону наблюдения в проходе. Для общей двери нарисуйте также отдельную зону внутри зала. При такой настройке система учитывает последовательность «дверь → зал». Одну зону используйте для выделенного входного прохода.
3. На обзоре магазина откройте монитор визитов и настройки. Выберите вход и добавьте реальные переходы: из какой камеры человек исчезает и на какой может появиться дальше. Для каждого направления измерьте минимальное и максимальное время в пути. Если проход двусторонний, добавьте обратное направление.
4. Откройте визиты и проведите сотрудника по маршруту. Входное наблюдение получает временный номер. Последующие наблюдения связываются по разрешённому направлению перехода, времени и совместимым признакам цвета одежды. Оператор видит текущую камеру при свежем наблюдении, траекторию в координатах кадра и историю переходов со ссылками на доступные записи. Между наблюдениями панель показывает последнюю камеру и время. Движение в слепой зоне остаётся неизвестным.
5. Проверьте встречный проход, два входа подряд, одновременный переход похожих покупателей, пропадание сигнала и восстановление приложения. При проверке сравнивайте ID с независимой ручной разметкой по исходному видео. Измерьте ложные объединения разных людей, разделение одного визита на несколько, долю успешно связанных переходов и задержку вывода на рабочем сервере.

После 30 минут без наблюдений визит перестаёт считаться активным. История хранится до 24 часов с последнего наблюдения визита. Номер относится к визиту в этот магазин. Система использует локальные треки детектора и цветовые признаки одежды. Ошибка детекции на входе может оставить покупателя без номера, разрыв входного трека может создать второй номер. Сходная одежда, плотная толпа, ИК-подсветка и несовместимые ракурсы снижают долю уверенных связей. Одновременное наблюдение человека на перекрывающихся камерах требует отдельной проверки: схему настраивают под последовательный переход между ракурсами.

### Маршрут с полкой, кассой и выходом на разных камерах

В обзоре выбранного магазина откройте настройку связи камер. Назначьте каждую из трёх ролей отдельной камере и существующей зоне наблюдения. Укажите измеренный интервал между полкой и выходом. Для просмотра полных маршрутов используйте журнал связей камер.

| Наблюдение | Результат |
|---|---|
| Единственный подходящий проход через все три зоны | Обычный маршрут в журнале с тремя исходными клипами |
| Подходящая пара у полки и выхода, касса наблюдалась и подходящего прохода через неё нет | Два клипа в карточке для ручной проверки |
| Несколько правдоподобных соответствий, недоступный снимок, разрыв покрытия | Автоматическая связь не подтверждается |
| Более позднее наблюдение опровергает прежнюю связь | Карточка показывает отзыв связи; предыдущее решение сотрудника доступно в истории |

Монитор визитов может обновляться во время наблюдения. Карточка для проверки потерь появляется позже: анализируются записи завершённых треков и ожидаются возможные конкурирующие наблюдения. Факт прохода через кассовую зону сам по себе не устанавливает оплату. Время реакции и точность на этих десяти физических камерах предстоит проверить на месте.

## Запуск на одной камере

Для новой установки из каталога проекта выполните команды. Пароль администратора будет в `credentials.txt`, панель по умолчанию слушает `http://localhost:8080`. Для существующей установки сохраните текущие данные и конфигурацию, сделайте резервную копию и пересоберите сервисы с уже используемыми профилями.

```bash
python3 scripts/setup.py
docker compose --profile nvr up -d --build
```

1. В разделе **«Объекты»** создайте объект с профилем **«Магазин / супермаркет»**. Для пилота только по маршруту достаточно модуля **«Люди в кадре»**. Выберите магазин в верхнем фильтре.
2. Подключите поток существующей камеры или регистратора. Примените настройки в разделе **«Камеры»**. Перед разметкой проверьте кадр, обновление видео и запись события человека в Frigate.
3. Откройте настройки камеры. Нарисуйте три отдельных непересекающихся полигона: полку (область пола, где стоит покупатель), место обслуживания у кассы и последний видимый участок перед выходом. Оставьте промежутки между полигонами. Для каждого укажите тип **«Наблюдение за маршрутом»**. Имена могут быть `shelf`, `checkout`, `exit_area`. Сохраните зоны и примените настройки Frigate.
4. В обзоре магазина нажмите **«Настроить маршрут по зонам»**, выберите камеру и назначьте три зоны. Включите маршрут. После изменения потока, зон или переноса камеры проверьте привязки и сохраните правило заново.
5. Проверьте три прохода на своём объекте из таблицы ниже. Сверьте время, источник видео и переход к нужному моменту в карточке. При потере видео проверьте состояние канала и наличие записи в архиве.

| Контрольный проход | Ожидаемое поведение |
|---|---|
| Сотрудник остановился у полки, обошёл кассу, вышел из кадра через размеченный выход | Одна карточка при завершении трека. Повторное получение события сохраняет решение оператора. |
| Сотрудник подошёл к полке, посетил кассу, затем вышел | Сигнал маршрута отсутствует. Наличие оплаты проверяется отдельно. |
| Сотрудник подошёл к выходу, затем вернулся в зал, или его потеряла камера до выхода | При зафиксированном возврате или недостаточном треке сигнал маршрута отсутствует. Проверьте журнал Frigate, чтобы различить эти случаи. |

Правило использует координаты у ног человека. Для подтверждения полки и выхода нужны как минимум две последовательные позиции в каждой зоне с интервалом от 0,4 с. Путь от полки до выхода должен занять до 60 с. Разрыв между соседними позициями более 8 с, окончание наблюдения более чем за 8 с до завершения трека или пересечение сегментом траектории зоны кассы исключают сигнал. Эти инженерные ограничения уменьшают число неоднозначных карточек и одновременно могут приводить к пропускам.

## Дополнительный анализ поведения

Установите веса из доверенного источника и проверьте полный проход модели на коротком локальном видео. Затем включите на объекте **«Экспериментальный анализ возможной кражи»**, а в настройках нужной камеры — **«Анализ событий объекта»**. Модули драк, допуска и мимики для этого режима не требуются. [Установка и контрольный прогон](MODELS.md#получение-и-проверка-весов-для-магазина).

В магазине планировщик проверяет 12-секундные фрагменты с шагом 6 с в периоды, когда Frigate видел человека. Он ждёт 20 с до запроса записи. Декодирование, очередь и обновление интерфейса добавляют задержку. Измерьте её на сервере магазина в часы пик. Видеофайлы можно проверять отдельно в разделе «Анализ видео». Оценка модели показывает силу сигнала и требует настройки под ракурс. Утверждение «вероятность кражи 90 %» из этой оценки получить нельзя.

## Работа смены и приёмка

Оператор открывает очередь **«Проверка возможной кражи»**, просматривает контекст и выбирает одно из решений: отклонить сигнал, оставить на проверке, отметить для разбора. Можно сохранить комментарий. Отметка для разбора остаётся рабочим решением сотрудника. Панель показывает сигналы в браузере. Данные о платеже, уведомления на телефон и автоматическая передача в кассу в этот сценарий не входят.

Копия видео анализа хранится 24 часа после завершения задания. Для событий камеры Glazza затем запрашивает оригинал в Frigate, пока тот доступен по сроку хранения NVR. Для загруженных файлов такой резервной копии в NVR нет. Журнал событий и решений по умолчанию хранится 30 дней.

На первой смене включите теневой режим работы персонала: оператор разбирает карточки и отмечает наблюдения. Отдельный сотрудник проверяет заранее выбранные полные периоды видео, включая время без сигналов. Затем руководитель получает число просмотренных и пропущенных эпизодов, лишних карточек на камеру-час, минуты работы оператора и время недоступности записи. Для масштабирования на другие магазины до проверки согласуйте с клиентом допустимую нагрузку и уровень пропусков. Точность, задержка и экономия на объектах пока не измерены. [Методика и команды оценки](THEFT_EVALUATION.md).
