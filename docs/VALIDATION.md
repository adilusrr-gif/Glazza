## Добавление детектора драк для колледжа

Проверка 23.10.2026: `python tests/real_fight_smoke.py` — **PASS**. Реальный VD-MIL и HTTP-путь загрузка → очередь → анализатор → событие → защищённое видео → решение оператора.

| Пример | Вход | Результат при пороге 0.8, 3 соседних окнах |
|---|---|---|
| RWF demo 1 | 16.17 с, 31 окно | Сигнал 12.5–16.0 с; минимум оценок в интервале 0.9584 |
| RWF demo 2 | 11.77 с, 22 окна | Сигнал 9.0–11.0 с; минимум оценок 0.9944 |
| Статичный контроль из первого кадра | 5 с, 9 окон | Нет сигналов; peak ≈ 3.12e-10 |

Источник двух демонстраций: [публичные GIF авторов RWF-2000](https://github.com/mchengny/RWF2000-Video-Database-for-Violence-Detection/tree/master/Images). Правая половина с графиком предсказания удалена **до** анализа, используется только видео слева. Исходные медиа не включены в Glazza. Это производные публичных demo, могут пересекаться с обучением; **не независимый benchmark, не измерение recall/precision**. Статичный контроль не оценивает ложные срабатывания на обычную активность студентов.

Прямой CPU-инференс занял около 4.72 и 2.57 с; сквозная обработка загруженных файлов — 8.18 и 6.11 с. Эти измерения не включают запись RTSP/Frigate и не обещают задержку на сервере колледжа. В отдельном upstream видео со стрельбой устойчивый сигнал не сформировался; обнаружение любого эпизода не гарантируется.

В unit/integration tests дополнительно проверены: active person до завершения события; 12-секундные записи и правильный API-маршрут; лимит очереди; отсутствие контроля драк при одной Face-модели; миграция SQLite; сохранение cursor; фиксация разрывов покрытия; подавление повторов без потери решения оператора; счётчик тревог.

Воспроизведение (зависимости анализатора и FFmpeg):

```bash
python3 scripts/models.py fight
python3 tests/real_fight_smoke.py
```

## Что не проверено

- Полный `docker compose up` и сборка Docker-образов: Docker Engine отсутствовал в среде разработки. Проверка конфигурации и сборка API-образа добавлены в GitHub Actions; локальный отчёт не является отчётом CI.
- Физическая IP-камера, RTSP, запись и архив Frigate. Контракт опроса / клипов проверялся с HTTP fixtures, конфигурация сверена с исходниками Frigate v0.18.2.
- Реальные веса VadCLIP и его классификация действий: официальная ссылка OneDrive вернула HTTP 403. Есть адаптер и установщик, но реального inference этой модели в проверке нет.
- Соответствие метрикам статьи VadCLIP, precision / recall на объекте, ложные тревоги на камеру-час, throughput, p95 latency, GPU, многосуточная работа.
- Полное аварийное восстановление NVR с архивом: проверена только SQLite backup-копия.

**Статус: пригодно для установки и технического пилота с явными ограничениями; промышленная приёмка не пройдена.**
