# Камеры, загрузка видео и тест с веб-камеры

Панель для работы с веб-камерой: **https://192.168.1.18:8443**.
Логин и пароль те же, что для HTTP-панели. При смене адреса нужно войти снова.

## Камеры разных производителей

В разделе «Камеры» нажмите «Подключить камеру», задайте название, идентификатор
и адрес видеопотока. Включите анализ событий и примените настройки.

| Источник | Пример |
|---|---|
| IP-камера RTSP / RTSPS | `rtsp://user:password@192.168.1.50:554/stream` |
| HTTP / HTTPS MJPEG | `http://192.168.1.50:8080/video` |
| HLS или HTTP-FLV | `https://camera.example/live.m3u8` |
| RTMP / RTMPS | `rtmp://camera.example/live/camera` |
| Камера ONVIF | RTSP-адрес медиапрофиля из настроек камеры |
| Камера ноутбука, USB-камера, камера телефона | «Анализ видео» → «Открыть веб-камеру» |

Нужен адрес самого видео, а не веб-страницы камеры. Автоматического поиска ONVIF
пока нет. Закрытые облачные камеры без доступного потока требуют отдельного адаптера.
USB-камера выбирается на устройстве, где открыт браузер; это режим тестовой записи,
а не постоянный источник NVR.

HTTP(S) и RTMP(S) проходят через FFmpeg/go2rtc с преобразованием в H.264,
чтобы Frigate мог записывать их. Это использует CPU. RTSP/RTSPS работают напрямую.
Адреса потоков с паролями не возвращаются в браузер после сохранения.

## Загруженные видео

В «Анализе видео» выберите MP4, MOV, WebM, MKV или AVI и нажмите «Запустить анализ».
Лимиты: 200 МБ, 120 секунд, разрешение до 4K. После очереди появится кнопка «Результат».
Воспроизведение исходного видео зависит от кодеков браузера; исходник можно скачать.
При отсутствии доступных моделей задание ждёт в очереди.

## Тест с веб-камеры

1. Откройте HTTPS-панель и войдите.
2. «Анализ видео» → «Открыть веб-камеру». Разрешите камеру в браузере.
3. Выберите устройство и длительность от 5 до 120 секунд.
4. Нажмите «Записать и анализировать». Запись остановится автоматически;
   её можно закончить раньше кнопкой «Завершить и анализировать».
5. Откройте результат в истории анализа. Такие задания помечены «Веб-камера».

Предпросмотр остаётся на устройстве. Отправляется записанный фрагмент, звук не
запрашивается. Закрытие окна во время записи отменяет отправку и выключает камеру.
Длительные записи WebM без заголовка длительности также проверяются на сервере.

Браузеры требуют защищённое подключение для доступа к камере. На сервере используется
локальный сертификат. Подтвердите его в браузере; если устройство требует доверенного
центра сертификации, установите `tls/ca.crt` из проекта или скачайте его по
https://192.168.1.18:8443/glazza-ca.crt. Закрытые ключи передавать не нужно.
На самом сервере также доступен http://localhost:8082.

## Проверки реализации

Проверены API и очередь, реальные декодеры MP4/MOV/WebM/MKV/AVI,
отклонение потокового WebM длиннее 120 секунд, живой синтетический MJPEG-поток
через отдельный Frigate и MediaRecorder в Chromium с тестовым устройством.
Физические камеры пользователя и все модели конкретных производителей требуют
проверки подключения на объекте.

Команды для повторения:

```bash
python -m pytest -q tests
# В окружении с FFmpeg и зависимостями анализатора:
python -m pytest -q tests/test_video_probe.py
# На развёрнутом сервере, с Playwright, FFmpeg и локальным .env:
python tests/browser_sources_smoke.py
```

Источники для интеграции: [Frigate: особые камеры](https://docs.frigate.video/configuration/camera_specific/),
[Frigate: restream](https://docs.frigate.video/configuration/restream/),
[MDN: доступ к камере](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia).
